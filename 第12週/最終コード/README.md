# 最終コード（第12週時点でのまとめ）

第2週〜第11週に散らばっていた試行錯誤版（varN）の中から，タイムスタンプが最も新しいものを
各パート1つずつ選んで集約したもの。Arduino/Processingとも「フォルダ名＝スケッチ名」の
規約に合わせて配置し直してあるので，そのままIDEで開ける。

## 重要：バイオリン／チェロ／フルートのArduinoは共通コード

輪唱（カノン）であるため，バイオリン・チェロ・フルートは**同じメロディーを時間差で演奏するだけ**で，
Arduino側のロジック（レーザ受信・拍カウント・メロディ配列）は3楽器とも同一。
実際に`Ketugou_instrument_var11.ino`（バイオリン採用元）と，旧フルート候補だった
`デモ演奏/Ketugou_instrument_var10.ino`を diff したところ差分はわずか4行（RESET送信の有無のみ）
だったため，**var11を3楽器共通のArduinoコードとして採用**した（チェロの「Arduino未発見」問題もこれで解消）。
一方コントラバスは，メロディを8音ベースパターンに差し替え・無限ループ化するなど明確に別ロジックのため，
独自コード（`Ketugou_contrabass.ino`）のまま。
Processing側（音色）は当然ながら4楽器ともそれぞれ別。

## 未解決の問題

- **var11採用は実機での動作未確認。** 旧候補`第11週/Ketugou_var6-1782884271057/`は
  アーキテクチャ自体が古い（ブロッキング方式）ため不採用としたが，本番前に一度は
  3楽器同時での通し動作を確認すること。
- **フルート（共通コード）のANGLE_REST/PLAYとブロック周期は，コントラバス側コードのコメントが
  想定する値（8小節毎）と異なる（4小節毎になっている）。** コントラバス側との整合性は未検証。
- 元の計画書に記載のファイル名（`vi.ino`/`vi_pro.pde`等）とは命名が一致していない。
  実際の作業ファイル名をそのまま踏襲し，フォルダ名で役割を明示する方針とした。
